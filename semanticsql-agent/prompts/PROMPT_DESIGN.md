# 提示词设计逻辑

## 提示词组合架构

SemanticSQL Agent使用两层提示词设计：

### 1. 系统提示词 (system/main.j2)
- **角色**：定义Agent的身份、能力和行为模式
- **内容**：
  - Agent角色定义
  - 可用工具列表
  - 标准工作流程（数据库分析 → 数据生成）
  - ReAct格式要求
  - 质量标准
- **参数**：
  - `{tools}` - 工具描述
  - `{tool_names}` - 工具名列表
  - `{database_name}` - 数据库名
  - `{count}` - 生成数量
  - `{memory_summary}` - 记忆状态

### 2. 任务提示词 (如 generation/training_data_generation.j2)
- **角色**：提供具体任务指令
- **内容**：极简的任务描述
- **原则**：
  - 不重复系统提示词中的流程说明
  - 只提供任务特定的信息
  - 相信Agent会按照系统流程执行

## 提示词组合方式

```python
ChatPromptTemplate.from_messages([
    ("system", system_prompt),      # 系统提示词
    ("human", "{input}"),          # 任务提示词
    ("assistant", "{agent_scratchpad}")  # Agent思考过程
])
```

## 设计理念

1. **职责分离**：
   - 系统提示词负责"如何做"
   - 任务提示词负责"做什么"

2. **避免重复**：
   - 流程说明只在系统提示词中定义一次
   - 任务提示词只需说明具体目标

3. **灵活性**：
   - 不同任务可以复用同一个系统提示词
   - 任务提示词可以很简洁

## 任务提示词示例

### 生成任务
```jinja2
任务：生成 {{ count }} 个SQL训练数据样本。
```

### 分析任务
```jinja2
任务：分析数据库 {{ database_name }} 的结构和业务含义。
```

### 优化任务
```jinja2
任务：优化以下SQL查询的性能：
{{ sql_query }}
```

## 最佳实践

1. **系统提示词**应该完整且自包含
2. **任务提示词**应该简洁明了
3. **参数传递**通过模板变量，而非重复说明
4. **信任Agent**按照系统流程自主执行
