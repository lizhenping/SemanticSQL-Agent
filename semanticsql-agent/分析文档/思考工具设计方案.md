# ThinkingTool 设计方案 - 简化版

## 1. 核心理念

**核心目标**：为任何工具提供智能思考增强，通过整合全局记忆提升结果质量

### 1.1 设计原则
- **简单输入**：接收目标工具名 + 原工具结果
- **记忆整合**：自动获取所有相关三元组记忆
- **透明输出**：返回增强的三元组集合，替换原结果
- **智能体控制**：由Agent决定何时调用

## 3. 智能体调用设计

### 3.1 Agent接口
```python
class SemanticSQLAgent:
    def execute_tool_with_thinking(self, tool_name: str, **params):
        # 1. 执行原工具
        original_result = self.tools[tool_name]._run(**params)
        
        # 2. 判断是否需要思考增强
        if self._should_use_thinking(tool_name, original_result):
            # 3. 调用ThinkingTool进行增强
            enhanced_result = self.thinking_tool._run(
                target_tool=tool_name,
                original_result=original_result
            )
            return enhanced_result
        else:
            return original_result
```

### 3.2 判断逻辑
```python
def _should_use_thinking(self, tool_name: str, result: TripleCollection) -> bool:
    # 简化的判断条件
    if len(result.triples) < 2:  # 结果太简单
        return True
    if len(self.memory.get_all_tool_names()) >= 3:  # 有丰富上下文
        return True
    return False
```
    
## 4. 调用示例

### 4.1 基本调用
```python
# 初始化
memory = TripleMemory()
agent = SemanticSQLAgent(memory)

# 简单使用
result = agent.execute_tool_with_thinking("sql_generation", question="查询用户")
print(f"结果: {len(result.triples)} 个三元组")
```

### 4.2 直接调用

## 5. 核心优势

### 5.1 接口简单
- **输入**: 目标工具 + 原结果
- **输出**: 增强的三元组集合
- **记忆**: 自动获取所有可用上下文

### 5.2 智能控制
- **Agent决策**: 由智能体动态判断何时使用
- **透明替换**: 直接替换原工具结果
- **灵活策略**: 判断逻辑可调整

### 5.3 架构兼容
- **三元组统一**: 完全兼容新架构
- **即插即用**: 无需修改现有工具
- **统一接口**: 使用标准三元组访问方式
    
## 6. 实施要点

### 6.1 开发优先级
1. **核心接口**: 先实现基本的输入-输出接口
2. **记忆访问**: 实现三元组记忆的获取和保存
3. **Agent集成**: 实现智能体的调用逻辑
4. **增强逻辑**: 后期完善具体的思考增强算法

### 6.2 技术要点
- **输入验证**: 检查target_tool和original_result的有效性
- **记忆获取**: 从所有工具获取三元组上下文
- **结果增强**: 基于上下文生成更优质的三元组
- **错误处理**: 增强失败时返回原结果

### 6.3 扩展点
- **专门化增强**: 针对不同工具的专门增强策略
- **轨迹记录**: 可选的思考过程记录功能  
- **性能优化**: 上下文缓存和增强结果缓存
