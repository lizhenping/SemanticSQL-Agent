# 验证工具统一设计方案

## 1. 工具概览

### 1.1 验证工具清单
- **sql_validation_tool**: SQL语法和逻辑验证
- **sql_execution_tool**: SQL执行和结果获取

### 1.2 设计目标
- **质量保证**: 确保生成的SQL在语法和逻辑上都正确
- **安全执行**: 安全地执行SQL并获取结果
- **结果分析**: 对执行结果进行基础分析和统计

## 2. 统一接口设计

### 2.1 基础接口
```python
class BaseValidationTool(BaseSemanticSQLTool):
    def _run(self, **params) -> TripleCollection:
        # 第1步：获取SQL生成阶段的三元组
        sql_context = self._get_sql_generation_context()
        
        # 第2步：执行验证/执行逻辑
        validation_result = self._validate_with_context(params, sql_context)
        
        # 第3步：输出三元组集合
        output_triples = self._format_validation_triples(validation_result)
        self.memory.save_triples(self.name, output_triples)
        return output_triples
```

```python

{"sql": "SELECT * FROM users WHERE id = 1"}

# sql_execution_tool  
{"sql": "SELECT COUNT(*) FROM orders", "database_config": {...}}
```

## 3. 各工具设计要点

### 3.1 SQL Validation Tool
**职责**: 验证SQL的语法正确性和逻辑合理性

#### 输入依赖
```python
# 主要输入：待验证的SQL语句
# 上下文依赖：
- schema_extraction: 验证表名和列名是否存在
- sql_generation: 获取SQL的生成上下文
- database_config: 数据库连接信息（用于结构验证）
```

#### 验证维度
```python
1. 语法验证 (Syntax Validation)
   - SQL语法是否正确
   - 关键字使用是否规范
   - 括号匹配是否正确

2. 结构验证 (Structure Validation)  
   - 表名是否存在
   - 列名是否存在于对应表中
   - 数据类型是否匹配

3. 逻辑验证 (Logic Validation)
   - JOIN条件是否合理
   - WHERE条件是否可能有结果
   - GROUP BY和聚合函数使用是否正确

4. 安全验证 (Security Validation)
   - 是否包含危险操作（DROP, DELETE等）
   - 是否有SQL注入风险
   - 查询复杂度是否过高
```

#### 输出三元组示例
```python
("sql_1", "syntax_valid", True)
("sql_1", "syntax_errors", [])
("sql_1", "tables_valid", True)
("sql_1", "missing_tables", [])
("sql_1", "columns_valid", True) 
("sql_1", "missing_columns", [])
("sql_1", "join_logic_valid", True)
("sql_1", "security_safe", True)
("sql_1", "estimated_complexity", "medium")
("sql_1", "validation_score", 0.95)
```

#### 验证策略
```python
def _validate_sql(self, sql: str) -> Dict:
    result = {
        "syntax_valid": True,
        "structure_valid": True, 
        "logic_valid": True,
        "security_safe": True,
        "errors": [],
        "warnings": []
    }
    
    # 1. 语法解析验证
    try:
        parsed = sqlparse.parse(sql)[0]
        result["syntax_valid"] = True
    except Exception as e:
        result["syntax_valid"] = False
        result["errors"].append(f"语法错误: {e}")
    
    # 2. 结构验证（基于schema三元组）
    schema_info = self._get_schema_from_memory()
    missing_tables = self._check_tables_exist(sql, schema_info)
    missing_columns = self._check_columns_exist(sql, schema_info)
    
    # 3. 逻辑验证
    logic_issues = self._check_query_logic(sql, schema_info)
    
    # 4. 安全验证
    security_issues = self._check_security_risks(sql)
    
    return result
```

### 3.2 SQL Execution Tool
**职责**: 安全执行SQL并收集执行结果和统计信息

#### 输入依赖
```python
# 主要输入：SQL语句 + 数据库配置
# 建议先经过sql_validation验证
# 上下文：sql_validation的验证结果
```

#### 执行策略
```python
def _execute_sql_safely(self, sql: str, db_config: dict) -> Dict:
    result = {
        "execution_success": False,
        "row_count": 0,
        "execution_time": 0.0,
        "result_preview": [],
        "error_message": None,
        "warnings": []
    }
    
    # 1. 预检查：确保是SELECT语句
    if not self._is_safe_query(sql):
        result["error_message"] = "只允许执行SELECT查询"
        return result
    
    # 2. 设置执行限制
    safe_sql = self._add_safety_limits(sql)
    
    # 3. 执行查询
    try:
        start_time = time.time()
        with database.get_connection(db_config) as conn:
            cursor = conn.execute(safe_sql)
            rows = cursor.fetchmany(100)  # 限制预览行数
            row_count = len(rows)
        
        result["execution_success"] = True
        result["execution_time"] = time.time() - start_time
        result["row_count"] = row_count
        result["result_preview"] = rows
        
    except Exception as e:
        result["error_message"] = str(e)
    
    return result
```

```python
("sql_1", "execution_time", 0.045)
("sql_1", "row_count", 1523)
("sql_1", "has_results", True)
("sql_1", "result_columns", ["user_id", "name", "email"])
("sql_1", "result_preview", [{"user_id": 1, "name": "Alice"}, ...])
("sql_1", "performance_rating", "good")
("sql_1", "memory_usage", "low")
```

#### 安全措施
```python
1. 查询类型限制
   - 只允许SELECT查询
   - 禁止DDL和DML操作
   - 禁止存储过程调用

2. 资源限制
   - 查询超时限制（默认30秒）
   - 结果集大小限制（最多10000行）
   - 内存使用限制

3. 权限控制
   - 使用只读数据库连接
   - 限制访问的数据库和表
   - 记录所有执行日志
```


### 4.2 验证决策逻辑
```python
def should_execute_sql(validation_result: TripleCollection) -> bool:
    """基于验证结果决定是否执行SQL"""
    
    for triple in validation_result:
        if triple.predicate == "syntax_valid" and not triple.object:
            return False
        if triple.predicate == "security_safe" and not triple.object:
            return False
        if triple.predicate == "validation_score" and triple.object < 0.8:
            return False
    
    return True
```

## 6. 增强策略

### 6.1 思考增强触发条件
- **验证失败**: 语法或逻辑验证不通过
- **执行异常**: SQL执行出现错误
- **性能问题**: 执行时间过长或资源消耗过大
- **结果异常**: 返回结果为空或与预期不符

### 6.2 增强效果
- **错误修复**: 基于验证错误自动修正SQL
- **性能优化**: 建议查询优化方案
- **结果解释**: 分析执行结果的合理性

## 7. 实施要点

### 7.1 开发优先级
1. **sql_validation**: 基础验证功能，必须优先实现
2. **sql_execution**: 执行和结果收集功能

### 7.2 技术关键点
- **SQL解析**: 使用sqlparse等库进行语法分析
- **数据库适配**: 支持不同数据库的语法差异
- **安全控制**: 严格的安全措施防止误操作
- **性能监控**: 查询性能和资源使用监控

### 7.3 错误处理
- **验证错误**: 提供详细的错误信息和修正建议
- **执行异常**: 安全的异常处理和错误恢复
- **超时处理**: 查询超时的优雅处理
- **资源保护**: 防止资源耗尽的保护机制
