# 分析工具统一设计方案

## 1. 工具概览

### 1.1 分析工具清单
- **schema_extraction_tool**: 数据库结构提取
- **domain_analysis_tool**: 业务领域分析  
- **field_analysis_tool**: 字段语义分析
- **column_analysis_tool**: 列级别分析
- **table_analysis_tool**: 表级别分析
- **er_analysis_tool**: 实体关系分析

### 1.2 设计目标
- **统一接口**: 所有分析工具使用相同的三元组输入-输出模式
- **渐进增强**: 后续工具基于前序工具的三元组结果进行增强分析
- **上下文感知**: 充分利用已有的分析结果进行深度分析

## 2. 统一接口设计

### 2.1 基础接口
```python
class BaseAnalysisTool(BaseSemanticSQLTool):
    def _run(self, database_config: dict = None, **kwargs) -> TripleCollection:
        # 第1步：获取上下文三元组
        context_triples = self._get_analysis_context()
        
        # 第2步：执行分析逻辑
        analysis_result = self._analyze_with_context(database_config, context_triples)
        
        # 第3步：输出三元组集合
        output_triples = self._format_analysis_triples(analysis_result)
        self.memory.save_triples(self.name, output_triples)
        return output_triples
```

### 2.2 输入参数
- **database_config**: 数据库连接配置（仅schema_extraction需要）
- **上下文三元组**: 从memory自动获取，无需显式传递

### 2.3 输出格式
```python
# 统一的三元组输出格式
output = TripleCollection()
output.add_triple(subject, predicate, object)

# 示例：
# schema_extraction -> ("table_users", "has_column", {"name": "id", "type": "int"})
# domain_analysis -> ("users_table", "belongs_to_domain", "user_management") 
# field_analysis -> ("user_id", "semantic_type", "primary_key")
```

## 3. 各工具设计要点

### 3.1 Schema Extraction Tool
**职责**: 提取NL2SQL需要的基本数据库结构信息：表、列、数据类型、注释

#### 输入设计（简化版）
```python
# 输入：简单的数据库连接参数
def _run(
    self,
    host: str,
    database: str,
    username: str, 
    password: str,
    port: int = 3306
) -> TripleCollection:
```

#### 输出三元组示例（三层基本结构）
```python
# 数据库层 - 包含哪些表
("database", "has_table", "users")
("database", "has_table", "orders")
("database", "has_table", "products")

# 表层 - 表注释和包含哪些列
("table:users", "table_comment", "用户信息表")
("table:users", "has_column", "id")
("table:users", "has_column", "username")
("table:users", "has_column", "email")

("table:orders", "table_comment", "订单信息表")
("table:orders", "has_column", "id")
("table:orders", "has_column", "user_id")
("table:orders", "has_column", "total_amount")

# 列层 - 数据类型和列注释
("column:users.id", "data_type", "int")
("column:users.id", "column_comment", "用户唯一标识")

("column:users.username", "data_type", "varchar")
("column:users.username", "column_comment", "用户名")

("column:orders.total_amount", "data_type", "decimal")
("column:orders.total_amount", "column_comment", "订单总金额")
```

**设计特点**：
- 极简输入：只需基本的数据库连接参数
- 三层清晰结构：数据库→表→列
- 专注核心信息：表名、列名、数据类型、注释
- 标准化数据类型：int、varchar、text、date、datetime、boolean、decimal

### 3.2 Domain Analysis Tool  
**职责**: 分析业务领域归属
```python
# 输入：从schema_extraction获取表结构三元组
# 输出三元组示例：
("users", "belongs_to_domain", "user_management")
("orders", "belongs_to_domain", "e_commerce")
("user_management", "related_to", "e_commerce")
```

### 3.3 Field Analysis Tool
**职责**: 分析字段语义类型
```python
# 输入：schema + domain分析结果
# 输出三元组示例：
("user.id", "semantic_type", "identifier")
("user.email", "semantic_type", "contact_info")
("order.amount", "semantic_type", "monetary_value")
```

### 3.4 Column Analysis Tool
**职责**: 深度分析列的业务含义
```python
# 输入：schema + field分析结果
# 输出三元组示例：
("user.created_at", "business_meaning", "用户注册时间")
("order.status", "enum_values", ["pending", "completed", "cancelled"])
```

### 3.5 Table Analysis Tool
**职责**: 分析表级别的业务逻辑
```python
# 输入：所有前序分析结果
# 输出三元组示例：
("users", "primary_entity", True)
("orders", "transaction_table", True)
("users_orders", "relationship_table", True)
```

### 3.6 ER Analysis Tool
**职责**: 分析实体关系
```python
# 输入：所有分析结果
# 输出三元组示例：
("users", "one_to_many", "orders")
("orders", "belongs_to", "users")
("relationship_strength", "strong", 0.9)
```

## 4. 执行顺序和依赖

### 4.1 推荐执行顺序
```
1. schema_extraction     (基础，无依赖)
2. domain_analysis      (依赖: schema_extraction)
3. field_analysis       (依赖: schema_extraction, domain_analysis)
4. column_analysis      (依赖: schema_extraction, field_analysis)
5. table_analysis       (依赖: 所有前序分析)
6. er_analysis          (依赖: 所有前序分析)
```

### 4.2 依赖关系
- **强依赖**: 必须等待前序工具完成
- **弱依赖**: 可以并行执行，但有前序结果时效果更好
- **增量分析**: 后续工具基于已有三元组进行增量分析

## 6. 增强策略

### 6.1 思考增强触发条件
- **分析结果过于简单**: 三元组数量 < 5
- **复杂数据库结构**: 表数量 > 10
- **领域识别不明确**: domain confidence < 0.7
- **字段语义模糊**: semantic_type = "unknown" 的比例 > 30%

### 6.2 增强效果
- **上下文整合**: 跨工具的信息关联和验证
- **语义推理**: 基于已知信息推断未知信息
- **质量提升**: 修正不准确的分析结果

## 7. 实施要点

### 7.1 开发优先级
1. **schema_extraction**: 作为基础必须优先实现
2. **domain_analysis**: 为后续分析提供业务上下文
3. **field_analysis**: 提供字段级语义信息
4. **其他工具**: 根据具体需求选择实现顺序

### 7.2 技术关键点
- **数据库适配**: 支持MySQL、PostgreSQL、SQLite等
- **增量分析**: 避免重复分析，提高效率
- **异常处理**: 数据库连接失败、权限不足等场景
- **缓存机制**: 分析结果缓存，避免重复计算
