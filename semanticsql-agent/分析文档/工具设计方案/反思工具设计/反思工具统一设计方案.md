## 2. 统一接口设计

### 2.1 基础接口
```python
class BaseReflectionTool(BaseSemanticSQLTool):
    def _run(self, **params) -> TripleCollection:
        # 第1步：获取全流程的三元组上下文
        full_context = self._get_full_workflow_context()
        
        # 第2步：执行反思分析
        reflection_result = self._reflect_on_workflow(params, full_context)
        
        # 第3步：输出三元组集合
        output_triples = self._format_reflection_triples(reflection_result)
        self.memory.save_triples(self.name, output_triples)
        return output_triples
```

```python
def _evaluate_workflow_completeness(self, context: Dict) -> Dict:
    """评估工作流的完整性"""
    
    completeness = {
        "schema_analysis": False,
        "domain_analysis": False, 
        "sql_generation": False,
        "sql_validation": False,
        "sql_execution": False,
        "overall_score": 0.0
    }
    
    # 检查各阶段是否完成
    available_tools = context.keys()
    
    if "schema_extraction" in available_tools:
        completeness["schema_analysis"] = True
    if "domain_analysis" in available_tools:
        completeness["domain_analysis"] = True
    if "sql_generation" in available_tools:
        completeness["sql_generation"] = True
    # ... 其他检查
    
    completed_stages = sum(completeness.values()[:-1])
    completeness["overall_score"] = completed_stages / 5.0
    
    return completeness
```

#### 3.2.2 结果质量评估
```python
def _evaluate_result_quality(self, context: Dict) -> Dict:
    """评估结果质量"""
    
    quality_metrics = {
        "sql_syntax_score": 0.0,
        "sql_logic_score": 0.0,
        "execution_success": False,
        "result_reasonableness": 0.0,
        "overall_quality": 0.0
    }
    
    # 1. SQL语法质量
    if "sql_validation" in context:
        validation_triples = context["sql_validation"]
        for triple in validation_triples:
            if triple.predicate == "syntax_valid":
                quality_metrics["sql_syntax_score"] = 1.0 if triple.object else 0.0
    
    # 2. 执行成功率
    if "sql_execution" in context:
        execution_triples = context["sql_execution"]
        for triple in execution_triples:
            if triple.predicate == "execution_success":
                quality_metrics["execution_success"] = triple.object
    
    # 3. 结果合理性
    quality_metrics["result_reasonableness"] = self._assess_result_reasonableness(context)
    
    # 计算总体质量分数
    quality_metrics["overall_quality"] = self._calculate_overall_quality(quality_metrics)
    
    return quality_metrics
```

#### 3.2.3 一致性检查
```python
def _check_consistency(self, context: Dict) -> Dict:
    """检查各阶段结果的一致性"""
    
    consistency_checks = {
        "schema_sql_consistency": 0.0,    # schema和SQL的一致性
        "question_sql_consistency": 0.0,  # 问题和SQL的一致性
        "domain_logic_consistency": 0.0,  # 领域逻辑一致性
        "overall_consistency": 0.0
    }
    
    # 1. 检查SQL中使用的表和列是否存在于schema中
    if "schema_extraction" in context and "sql_generation" in context:
        consistency_checks["schema_sql_consistency"] = self._check_schema_sql_match(
            context["schema_extraction"], 
            context["sql_generation"]
        )
    
    # 2. 检查生成的SQL是否回答了原问题
    if "question_generation" in context and "sql_generation" in context:
        consistency_checks["question_sql_consistency"] = self._check_question_sql_match(
            context["question_generation"],
            context["sql_generation"]
        )
    
    # 3. 检查业务逻辑一致性
    consistency_checks["domain_logic_consistency"] = self._check_domain_logic(context)
    
    # 计算总体一致性分数
    consistency_checks["overall_consistency"] = np.mean([
        consistency_checks["schema_sql_consistency"],
        consistency_checks["question_sql_consistency"], 
        consistency_checks["domain_logic_consistency"]
    ])
    
    return consistency_checks
```

### 3.3 改进建议生成

#### 3.3.1 基于问题的建议
```python
def _generate_improvement_suggestions(self, quality_metrics: Dict, consistency_checks: Dict) -> List[str]:
    """基于评估结果生成改进建议"""
    
    suggestions = []
    
    # 语法问题
    if quality_metrics["sql_syntax_score"] < 0.8:
        suggestions.append("建议加强SQL语法验证，使用更严格的语法检查")
    
    # 执行问题
    if not quality_metrics["execution_success"]:
        suggestions.append("SQL执行失败，需要检查表名、列名和数据类型")
    
    # 一致性问题
    if consistency_checks["schema_sql_consistency"] < 0.8:
        suggestions.append("SQL与数据库结构不一致，建议增强schema分析")
    
    if consistency_checks["question_sql_consistency"] < 0.8:
        suggestions.append("SQL未能正确回答原问题，需要改进问题理解")
    
    # 结果合理性问题
    if quality_metrics["result_reasonableness"] < 0.7:
        suggestions.append("查询结果不够合理，建议增加业务逻辑验证")
    
    return suggestions
```

## 5. 增强策略

### 5.1 思考增强触发条件
- **质量分数较低**: 整体质量分数 < 0.7
- **一致性问题**: 一致性分数 < 0.8
- **执行失败**: SQL执行不成功
- **结果异常**: 查询结果明显不合理

### 5.2 增强效果
- **深度分析**: 更详细的问题诊断和原因分析
- **精准建议**: 基于具体问题提供针对性改进建议
- **趋势分析**: 分析多次执行的质量趋势

## 6. 实施要点

### 6.1 开发优先级
1. **基础评估**: 实现基本的质量和一致性评估
2. **建议生成**: 基于评估结果生成改进建议
3. **深度反思**: 增加更复杂的分析维度

### 6.2 技术关键点
- **评估算法**: 合理的质量评估算法和权重设置
- **一致性检查**: 准确的跨阶段一致性验证
- **建议生成**: 实用的改进建议生成策略
- **性能考虑**: 反思分析的计算效率

### 6.3 评估标准
- **准确性**: 反思评估的准确性
- **有用性**: 改进建议的实用价值
- **及时性**: 反思分析的响应速度
- **全面性**: 评估覆盖的维度完整性

## 7. 扩展方向

### 7.1 未来增强
- **学习能力**: 基于历史反思结果学习优化
- **对比分析**: 与其他类似查询的对比分析  
- **用户反馈**: 整合用户对结果的反馈
- **自动修正**: 基于反思结果自动触发修正流程

### 7.2 集成价值
反思工具作为整个NL2SQL系统的"质量检查器"，为系统的持续改进提供数据支持，确保生成结果的高质量和可靠性。
