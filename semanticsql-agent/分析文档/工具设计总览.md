# SemanticSQL-Agent 工具设计总览

## 1. 设计理念

### 1.1 核心原则
基于ThinkingTool的成功简化设计，所有工具采用统一的**输入-输出接口**和**三元组记忆架构**：

- **统一接口**: 所有工具都使用 `_run(**params) -> TripleCollection` 接口
- **三元组驱动**: 输入和输出都基于三元组集合
- **上下文感知**: 自动从memory获取所需的上下文三元组
- **即插即用**: 智能体可以动态调用任何工具并进行思考增强

### 1.2 架构统一性
```
每个工具的标准流程：
第1步：输入 - 获取参数 + 从memory获取上下文三元组
第2步：处理 - 基于上下文进行内部处理（临时数据，用完即丢）
第3步：输出 - 生成三元组集合，保存到memory并返回
```

## 2. 工具分类和职责

### 2.1 分析工具 (Analysis Tools) - 6个
**阶段定位**: 第一阶段，数据库和业务理解

| 工具名称 | 核心职责 | 输入依赖 | 输出三元组类型 |
|---------|---------|---------|---------------|
| schema_extraction | 数据库结构提取 | 数据库连接参数 | 表-列-类型基本三元组 |
| domain_analysis | 业务领域识别 | schema结构 | 领域归属、业务概念 |
| field_analysis | 字段语义分析 | schema + domain | 字段语义类型 |
| column_analysis | 列级深度分析 | 前序分析结果 | 列的业务含义 |
| table_analysis | 表级业务逻辑 | 所有前序结果 | 表的业务角色 |
| er_analysis | 实体关系分析 | 所有分析结果 | 表间关系信息 |

**执行顺序**: schema_extraction → domain_analysis → field_analysis → column_analysis → table_analysis → er_analysis

### 2.2 生成工具 (Generation Tools) - 3个
**阶段定位**: 第二阶段，基于分析结果进行内容生成

| 工具名称 | 核心职责 | 输入依赖 | 输出三元组类型 |
|---------|---------|---------|---------------|
| scenario_operation | 场景操作生成 | 所有分析结果 | 业务场景、操作类型 |
| question_generation | 问题生成 | 场景 + 分析结果 | 自然语言问题 |
| sql_generation | SQL查询生成 | 问题 + 所有上下文 | SQL语句、查询信息 |

**执行顺序**: scenario_operation → question_generation → sql_generation（或直接 question → sql_generation）

### 2.3 验证工具 (Validation Tools) - 2个
**阶段定位**: 第三阶段，质量保证和执行

| 工具名称 | 核心职责 | 输入依赖 | 输出三元组类型 |
|---------|---------|---------|---------------|
| sql_validation | SQL语法逻辑验证 | SQL + schema信息 | 验证结果、错误信息 |
| sql_execution | SQL安全执行 | 验证通过的SQL | 执行结果、性能信息 |

**执行顺序**: sql_validation → sql_execution

### 2.4 反思工具 (Reflection Tools) - 1个
**阶段定位**: 第四阶段，质量评估和改进

| 工具名称 | 核心职责 | 输入依赖 | 输出三元组类型 |
|---------|---------|---------|---------------|
| sql_reflection | 全流程质量评估 | 所有阶段结果 | 质量分数、改进建议 |

### 2.5 思考工具 (Thinking Tools) - 1个
**特殊定位**: 横跨所有阶段的增强工具

| 工具名称 | 核心职责 | 输入依赖 | 输出三元组类型 |
|---------|---------|---------|---------------|
| thinking_tool | 智能思考增强 | 任何工具的结果 + 全局上下文 | 增强后的三元组 |

## 3. 统一接口规范

### 3.1 工具基类
```python
class BaseSemanticSQLTool:
    def __init__(self, memory: TripleMemory):
        self.memory = memory
    
    def _run(self, **params) -> TripleCollection:
        """统一的执行接口"""
        # 子类必须实现此方法
        pass
```

### 3.2 输入参数规范
```python
# 分析工具
schema_extraction(host: str, database: str, username: str, password: str, port: int = 3306)
domain_analysis()  # 无需参数，自动获取schema
field_analysis()   # 无需参数，自动获取上下文

# 生成工具  
scenario_operation(domain: str = None, complexity: str = "medium")
question_generation(scenario_info: dict = None, question_count: int = 5)
sql_generation(question: str)

# 验证工具
sql_validation(sql: str)
sql_execution(sql: str, database_config: dict)

# 反思工具
sql_reflection(original_question: str = None, reflection_depth: str = "medium")

# 思考工具
thinking_tool(target_tool: str, original_result: TripleCollection)
```

### 3.3 输出格式规范
所有工具都返回 `TripleCollection`，包含：
- `subject`: 主体（表名、字段名、SQL等）
- `predicate`: 关系（has_column、generates_sql等）
- `object`: 客体（具体值、结构化数据等）

## 4. 智能体调用模式

### 4.1 标准工作流
```python
# 完整的四阶段工作流
result = agent.execute_workflow(task="分析数据库并生成查询")

# 阶段包括：
# 1. Analysis Phase: 所有分析工具
# 2. Generation Phase: 场景、问题、SQL生成  
# 3. Validation Phase: 验证和执行
# 4. Reflection Phase: 质量评估
```

### 4.2 灵活调用
```python
# 单工具调用
result = agent.execute_tool("sql_generation", question="查询用户")

# 带思考增强的调用
result = agent.execute_tool_with_thinking("sql_generation", question="复杂查询")

# 阶段调用
result = agent.execute_phase("analysis", database_config=config)
```

### 4.3 思考增强决策
智能体根据以下条件动态决定是否使用ThinkingTool：
- **结果质量**: 三元组数量、内容丰富度
- **任务复杂度**: 参数复杂性、涉及表数量
- **上下文丰富度**: 可用三元组数量
- **历史经验**: 类似任务的成功率

## 6. 关键设计决策

### 6.1 为什么选择三元组架构？
- **统一性**: 所有数据都用相同格式存储和传递
- **灵活性**: 可以表达任意复杂的关系和结构
- **扩展性**: 新工具只需遵循三元组格式即可集成
- **性能**: 避免复杂的数据格式转换

### 6.2 为什么采用内部处理模式？
- **记忆纯净**: 只存储最终的结构化结果
- **处理灵活**: 每个工具可以用最适合的方式处理数据
- **性能优化**: 临时数据不持久化，减少内存占用

### 6.3 为什么智能体控制思考增强？
- **动态决策**: 根据实际情况决定是否需要增强
- **透明替换**: 增强结果直接替换原结果
- **即插即用**: 无需修改现有工具代码

### 8.2 架构设计说明

**模块职责划分**：
- **config/**: 全局配置管理，包括数据库配置和系统设置
- **core/**: 核心通用组件，提供状态管理、记忆系统和工作流架构
- **tools/**: 按功能分组的工具集，每组工具具有独立的职责和数据模型
- **prompts/**: 模板化的提示词管理，支持Jinja2动态渲染
- **agent/**: ReAct智能体的封装和控制逻辑
- **utils/**: 辅助工具和公共服务组件

**就近原则体现**：
- 通用结构放在core：TripleOutput, ToolResult等所有工具都使用的基础结构
- 工具特定结构放在各工具组内：ThinkingResult, ValidationResult等专用结构
- 降低模块间耦合度，提高系统可维护性

这个架构与工具设计方案完美结合，为统一的三元组驱动工具生态提供了清晰的组织结构。
