# 分析工具 API 文档

## 概述

分析工具负责深度理解数据库的结构和业务语义。所有分析工具都继承自 `BaseAnalysisTool`，并实现了统一的输入验证和内存管理机制。

## 基类 BaseAnalysisTool

```python
class BaseAnalysisTool(BaseTool):
    """分析工具基类"""
    
    def get_analysis_from_memory(self, memory: Dict[str, Any], analysis_type: str) -> Dict[str, Any]:
        """从memory中获取特定类型的分析结果"""
```

### 统一输入格式

所有分析工具（除 SchemaExtractionTool 外）都接受 memory 参数：

```python
class AnalysisToolInput(BaseModel):
    """分析工具基础输入类"""
    memory: Dict[str, Any] = Field(description="包含数据库分析结果的记忆")
```

memory 参数支持：
- Dict 格式：直接传入字典
- JSON 字符串：自动解析为字典

## 1. SchemaExtractionTool

提取数据库的完整结构信息。

### 工具信息

- **名称**: `schema_extraction`
- **描述**: 提取数据库的完整结构信息，包括表、列、索引、外键等

### 输入参数

```python
class SchemaExtractionInput(BaseModel):
    database_name: str = Field(description="数据库名称")
    include_views: bool = Field(default=False, description="是否包含视图")
    include_indexes: bool = Field(default=True, description="是否包含索引信息")
    sample_data: bool = Field(default=False, description="是否包含样本数据")
    tables: List[str] = Field(default_factory=list, description="指定要提取的表（空则提取所有）")
```

### 输出格式

```python
{
    "database_name": "shop_db",
    "tables": [
        {
            "name": "users",
            "columns": [
                {
                    "name": "id",
                    "type": "int",
                    "nullable": false,
                    "key": "PRI",
                    "default": null,
                    "extra": "auto_increment"
                }
            ],
            "indexes": ["PRIMARY", "idx_email"],
            "foreign_keys": [],
            "row_count": 10000
        }
    ],
    "table_count": 10,
    "extraction_params": {
        "include_views": false,
        "include_indexes": true,
        "sample_data": false
    }
}
```

### 使用示例

```python
# Agent 调用格式
Action: schema_extraction
Action Input: {"database_name": "shop_db", "include_indexes": true}
```

- **名称**: `domain_analysis`
- **描述**: 分析数据库的业务领域，识别主要业务场景和数据特征

### 输入参数

```python

    """领域分析输入"""
```

- `schema_info` 或 `schema_extraction`: 数据库结构信息

### 输出格式

```python
{
    "primary_domain": "电子商务",
    "sub_domains": ["用户管理", "商品管理", "订单处理", "支付系统"],
    "business_entities": {
        "users": "用户实体",
        "products": "商品实体",
        "orders": "订单实体"
    },
    "key_features": [
        "多用户系统",
        "商品分类管理",
        "订单状态流转",
        "支付集成"
    ],
    "domain_confidence": 0.85,
    "analysis_notes": "基于表名和字段特征，判断为电商系统"
}
```


## 6. ERAnalysisTool

分析表之间的实体关系。

### 工具信息

- **名称**: `er_analysis`
- **描述**: 分析数据库表之间的实体关系，识别外键关系和隐式关联

### 输入参数

```python
class ERAnalysisInput(AnalysisToolInput):
    """ER分析输入"""
    memory: Dict[str, Any] = Field(description="包含数据库分析结果的记忆")
    analyze_implicit: bool = Field(default=True, description="是否分析隐式关系")
    depth: int = Field(default=2, description="关系分析深度")
```

### 需要的内存数据

- 所有之前的分析结果

### 输出格式

```python
{
    "relationships": [
        {
            "from_table": "orders",
            "to_table": "users",
            "type": "many-to-one",
            "join_condition": "orders.user_id = users.id",
            "relationship_name": "用户的订单",
            "is_explicit": true
        }
    ],
    "relationship_summary": {
        "total_relationships": 15,
        "explicit_relationships": 10,
        "implicit_relationships": 5
    },
    "entity_hierarchy": {
        "核心实体": ["users", "products"],
        "依赖实体": ["orders", "payments"],
        "子实体": ["order_items", "product_reviews"]
    }
}
```

## 使用流程

分析工具的标准使用流程：

1. **schema_extraction** → 获取数据库物理结构
2. **domain_analysis** → 理解业务领域
3. **field_classification** → 分类字段类型
4. **column_meaning_analysis** → 分析列的业务含义
5. **table_meaning_analysis** → 理解表的职责
6. **er_analysis** → 分析表间关系

每个工具的结果都会保存到 memory 中，后续工具可以访问之前的所有分析结果。

## 错误处理

所有分析工具使用统一的错误处理：

```python
from models.exceptions import ToolExecutionError

try:
    result = tool._run(memory=memory_data)
except Exception as e:
    raise ToolExecutionError(
        tool_name=tool.name,
        reason=f"分析失败: {str(e)}"
    )
```

## 最佳实践

1. **顺序执行**：按照推荐的顺序执行分析工具
2. **结果复用**：利用 memory 避免重复分析
3. **错误重试**：某个分析失败时可以单独重试
4. **增量分析**：可以只分析特定的表或字段
5. **结果验证**：使用 sql_reflection 验证分析准确性
