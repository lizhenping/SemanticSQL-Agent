## 9. 具体代码修改要点

### 9.1 LangChain 集成（重大改动）
当前代码**完全没有使用 LangChain**，需要全面重构：
- BaseAgent 需要重写，使用 LangChain 的 Agent 框架
- 安装 langchain 包：`pip install langchain langchain-openai`
- 使用 AgentExecutor 和 create_react_agent
- 工具需要继承自 `langchain.tools.BaseTool` 而不是自定义的 BaseTool
- 记忆系统使用 `langchain.memory.BaseMemory`

### 9.2 参数传递统一（所有工具都需要修改）
当前状态：
- domain_analysis_tool 使用 (schema_info, sample_data)
- sql_generation_tool 使用 (question, schema_info, operations, dialect)
- 其他工具也都使用分散的参数

需要改为：
- 所有工具的 `_run` 方法统一接收 `memory` 参数
- 从 memory 中获取需要的信息

### 9.3 错误处理统一
当前使用了部分自定义异常，但不完整：
- 需要全面使用 `models/exceptions.py` 中定义的异常
- 删除如 GenerationError 等未定义的异常
- 统一错误码和错误信息格式

### 9.4 流程控制
当前 BaseAgent 使用硬编码的 ReAct 循环，需要改为：
- 使用 LangChain 的 Agent 自主决策机制
- 删除硬编码的步骤控制
- sql_reflection 需要返回 problem_source、root_cause_analysis、recommended_action

## 10. 测试文件修改

- 使用统一的异常处理

## 11. 代码与设计的主要差异总结

### 11.1 核心架构差异
1. **完全没有使用 LangChain**
   - 当前：自定义的 BaseAgent、BaseTool、记忆管理
   - 应该：使用 LangChain 的标准组件

2. **Agent 架构不符合设计**
   - 当前：硬编码的 ReAct 循环，手动管理工具调用
   - 应该：LangChain AgentExecutor 自主决策

3. **工具参数不统一**
   - 当前：每个工具有不同的参数（schema_info, question, operations等）
   - 应该：统一使用 memory 参数

4. **缺失关键模块**
   - 缺少：utils/memory.py（记忆管理）
   - 缺少：utils/callbacks.py（回调处理）
   - 缺少：tools/analysis_tools/column_meaning_tool.py
   - 缺少：tools/analysis_tools/table_meaning_tool.py

5. **CLI 功能不符**
   - 当前：有 query 命令（单次SQL生成）
   - 应该：只有 generate 命令（批量训练数据生成）

### 11.2 需要的依赖包
```bash
pip install langchain==0.1.0
pip install langchain-openai==0.0.2
pip install langchain-community==0.0.10
```
