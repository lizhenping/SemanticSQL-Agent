# SemanticSQL Agent 命令行指令

## 系统概述
SemanticSQL Agent 是一个**智能体驱动的NL2SQL训练数据生成系统**。通过ReAct模式，Agent自主分析数据库、生成问题、创建SQL、执行验证并反思优化，最终输出高质量的训练数据集。

## 系统配置

### 1. VLLM模型服务启动
```bash
CUDA_VISIBLE_DEVICES=2 vllm serve /root/autodl-tmp/model/Qwen3-14B \
  --host 0.0.0.0 --port 9991 \
  --trust-remote-code --dtype auto \
  --max-model-len 32768 --max-num-seqs 256 \
  --gpu-memory-utilization 0.92 --tensor-parallel-size 1 \
  --served-model-name "Qwen3-14B"
```

### 2. 环境激活
```bash
source activate alphasql
cd /root/autodl-tmp/nl2sql/NL2SQL/trae-agent/semanticsql-agent
```

## 核心执行命令

### 主要功能：DataGenerationAgent智能数据生成
```bash

python main.py generate 100 dataset.json

# 7. sql_generation → 生成对应SQL
# 8. sql_execution → 执行验证
# 9. sql_reflection → 反思分析
# 10. 回退修正（如果发现问题）

# 实际使用示例
```

## 智能体工作流程

### DataGenerationAgent自主决策流程
```
用户命令: python main.py generate 20 training_data.json

Agent完整执行过程（提示词驱动，无硬编码）:

📊 数据库分析阶段（完整记忆）:
1. 🤔 Thought: "需要生成20条训练数据，先完整分析数据库结构并记忆"
2. 🔧 Action: extract_schema
3. 👁️ Observation: "发现9个表：aid_info、sjckc_zyccq_htjcxx等合同管理表"
4. 🤔 Thought: "基于表名分析业务领域特征"
5. 🔧 Action: domain_analysis  
6. 👁️ Observation: "识别为政务合同管理领域，confidence=0.95"
7. 🤔 Thought: "对字段进行语义分类"
8. 🔧 Action: field_classification
9. 👁️ Observation: "分类完成：aid_type(分类)、amount(金额)、date(时间)"
10. 🤔 Thought: "分析表之间的关系"
11. 🔧 Action: er_analysis
12. 👁️ Observation: "htbzh是核心关联字段，连接多个合同表"

🎯 智能生成阶段（基于记忆）:
13. 🤔 Thought: "基于政务合同管理特征，生成业务查询场景"
14. 🔧 Action: scenario_generation
15. 👁️ Observation: "生成了合同统计、资金分析、进度查询等场景"
16. 🤔 Thought: "为第一个场景生成自然语言问题"
17. 🔧 Action: question_generation
18. 👁️ Observation: "生成问题：查询aid_info表的记录总数"
19. 🤔 Thought: "为此问题生成SQL查询"
20. 🔧 Action: sql_generation
21. 👁️ Observation: "生成SQL：SELECT COUNT(*) FROM aid_info"

✅ 执行验证阶段（每条必须）:
22. 🤔 Thought: "执行SQL验证其正确性"
23. 🔧 Action: sql_execution
24. 👁️ Observation: "SQL执行成功，返回1行：count=156"
25. 🤔 Thought: "分析执行结果，评估质量"
26. 🔧 Action: sql_reflection
27. 👁️ Observation: "执行时间0.02s，结果合理，质量良好"

🔄 反思决策：
28. 🤔 Thought: "质量评估通过，继续生成下一条数据..."
    [如果reflection发现问题，会回退到相应工具重新生成]

[重复生成流程直到完成20条高质量数据]

💾 最终输出:
29. 🤔 Thought: "任务完成，保存20条训练数据到文件"
```

### 🔄 反思-修正循环示例
```
场景：Agent生成的SQL执行失败

🔧 Action: sql_execution
👁️ Observation: "SQL执行失败：Unknown column 'aid_amount'"
🤔 Thought: "SQL中的字段名错误，需要重新生成"
🔧 Action: sql_generation (重新调用)
👁️ Observation: "修正后SQL：SELECT amount FROM aid_info"  
🔧 Action: sql_execution (再次验证)
👁️ Observation: "SQL执行成功"
🔧 Action: sql_reflection
👁️ Observation: "质量良好，接受此数据"
```

## 系统特性

### 🤖 完整Agent驱动架构
- **12工具完整链**: 分析→生成→验证→反思→思考全覆盖
- **提示词引导**: 所有流程由精心设计的提示词引导，无硬编码
- **无降级机制**: 完全依赖LLM和Agent智能决策，移除所有模板/规则降级
- **记忆机制**: 数据库分析一次完成，结果贯穿整个生成过程
- **ReAct模式**: Thought → Action → Observation 循环执行
- **自主决策**: Agent动态选择工具调用顺序和执行策略

### 🔄 反思-修正循环
- **执行后反思**: 每个SQL生成后必须执行并反思分析
- **智能回退**: 发现问题时自动回退到相应步骤重新生成
- **质量保证**: SQL错误→重新生成SQL，问题不合理→重新生成问题
- **深度思考**: 复杂情况下调用sequential_thinking进行深度分析

### 🎯 高质量输出
- **真实执行验证**: 所有SQL均在testdb数据库中实际执行验证
- **语法正确**: 生成的SQL符合MySQL语法规范
- **语义匹配**: 问题与SQL语义完全对应
- **多样化覆盖**: 统计、查询、聚合、关联等多种SQL类型
- **领域相关**: 针对政务合同管理真实业务场景
